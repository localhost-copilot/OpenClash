# 设备出口（Device Egress）设计规格 v1

目标：在 OpenClash 里选一台局域网设备，让它的全部 IPv4 外网流量只走一个节点或策略组。
OpenClash 停止、重启、启动失败、内核崩溃、路由器重启、防火墙重载时，这台设备断网，绝不直连。

## 0. 现有界面评审（QWRT design 主题，1440 和 390 宽度截图）

1. 插件设置页在正文前有 10 行「注意」，加上两排共 15 个子标签，真正的内容被推到了第二屏。新功能不能塞进这里。
2. 「来源流量访问控制」用的是 CBI 表格，有 9 列。390 宽度下横向溢出（「地址类」被截断），而且看不到当前状态。按设备做的配置不能沿用这种表格。
3. 黑白名单只认 IP 或 MAC 字符串，没有设备名，也看不出 IP 是否固定。新功能必须把设备名、IP、MAC 以及「IP 是否固定」一起展示。
4. 「保存配置」和「应用配置」分成两个按钮，用户很容易只点了保存、以为已经生效。这个功能关系到安全，每个操作都要一步生效。
5. 运行状态页的卡片、分段按钮和状态徽标（「Meta 运行中」）在手机上表现不错。新页面沿用这套卡片风格，不用 CBI。

## 1. 入口与信息架构

- 顶部导航新增「设备出口」，放在「插件设置」和「覆写设置」之间（controller order 35）。
- 新页面是自定义 view（htm+JS）加 JSON 接口，不用 CBI。
- 每个操作（添加、编辑、暂停、恢复、删除）一步完成保存和应用，页面上没有「保存」和「应用」按钮。

保存后：

· IPv6 外网会被阻断

· OpenClash 正在运行时会重新加载，所有设备的连接会中断几秒

- 设备列表合并三个来源：邻居表、DHCP 租约、静态租约（`dhcp.@host`），按 MAC 去重。名称优先取静态租约名，其次 DHCP 主机名，最后用 MAC。
- 「固定这个 IP」会写入一条 `dhcp host`（name、mac、ip）并重载 dnsmasq，按钮随后变为「已固定」。这一步独立完成，不依赖是否保存设备。
- OpenClash 没在运行时，节点和策略组从当前配置文件读取，不调用 API；策略组的「当前」一栏不显示。
- 策略组是否「包含 DIRECT」要递归检查：子组也算；`include-all` 和 provider 展开后的成员也算。DIRECT 和 COMPATIBLE 视为直连，REJECT 不算直连。
- 「保存并应用」执行时按钮显示「正在应用…」并禁用，弹层不可关闭。

## 5. 状态模型

### 5.1 总状态卡

| 条件 | 圆点 | 标题 | 副文案 |
|---|---|---|---|
| 没有启用的设备 | 灰 | 未设置设备出口 | 添加设备后，这台设备在 OpenClash 停止时会断网，不会直连。 |
| 有启用的设备且保护规则在位 | 绿 | 断网保护已生效 | N 台设备：X 台走节点，Y 台已阻断 |
| 有启用的设备但保护规则缺失或与配置不一致 | 红 | 断网保护未生效 | 这些设备在 OpenClash 停止时可能直连。[重新应用保护] |
| 连续 2 次取状态失败 | 灰 | 状态未知 | 无法获取状态，正在重试。 |

- 状态未知时，所有设备的状态徽标都显示「未知」。不能保留之前的绿色状态。

### 5.2 设备状态（按顺序判断，命中第一条即停）

| 条件 | 徽标 | 副文案 | 行内操作 |
|---|---|---|---|
| 已暂停 | ○ 已暂停（灰） | 按普通规则上网 | 恢复 |
| 保护规则不在位 | ● 未保护（红） | 停止时可能直连 | 重新应用保护 |
| OpenClash 未运行 | ● 已阻断（红） | OpenClash 未运行 | — |
| OpenClash 正在启动或停止 | ● 已阻断（橙） | OpenClash 正在启动 | — |
| 出口不在当前配置中 | ● 已阻断（红） | 出口不在当前配置中 | 修改出口 |
| 策略组包含直连 | ● 已阻断（红） | 策略组包含 DIRECT | 修改出口 |
| 内核里没有这台设备的入站 | ● 已阻断（红） | 内核未加载设备出口，查看运行日志 | 运行日志 |
| 设备当前 IP 与绑定 IP 不同 | ● 已阻断（红） | 设备 IP 已变为 192.168.50.77 | 改用新 IP |
| 以上都不满足 | ● 走节点（绿） | 节点 · 89 ms，或策略组 · 当前 日本 03 | 测试延迟 |

- 是否在线（在线 / 离线）是附加标注，不影响上面的状态。
- 测试延迟超时只显示「超时」（橙色文字），状态仍为「走节点」：这时设备不能上网，但也不会直连。

## 6. 确认弹窗文案

- **删除**：标题「删除 MacBook-Pro 的设备出口？」，正文「删除后，这台设备会按 OpenClash 的普通规则上网；OpenClash 停止时它会直连。」，按钮 [取消] [删除]（红色）。
- **暂停**：标题「暂停 MacBook-Pro 的设备出口？」，正文「暂停期间，这台设备按普通规则上网；OpenClash 停止时它会直连。」，按钮 [取消] [暂停]。
- **恢复**：不需要确认，直接执行。

## 7. 校验与错误文案

- 同一个 MAC 已添加：`这台设备已经设置过出口。`
- 同一个 IP 已被其他 MAC 使用：`这个 IP 已被 <名称> 使用。`
- IP 不在局域网网段：`IP 不在局域网网段 192.168.50.0/24 内。`
- IP 等于路由器自身地址：`不能使用路由器自身的地址。`
- MAC 格式错误：`MAC 地址格式不正确。`
- 没有选择出口：`请选择出口。`
- 出口是策略组且包含直连：`这个策略组包含 DIRECT，可能直连，不能用于设备出口。`
- 设备数量超过 32 台：`最多设置 32 台设备。`
- 保护规则写入失败：`保护规则写入失败，没有保存。`，下方可展开查看 nft 输出。此时配置必须回滚。
- 名称、节点名、主机名一律按纯文本渲染，不能当作 HTML 插入（emoji 和特殊字符都要原样显示）。

| 条件 | 文案 |
|---|---|
| 防火墙开启了软件或硬件流量卸载 | 已开启流量卸载，已建立的连接可能绕过断网保护。建议关闭。 [前往防火墙设置] |

## 9. 交互细节

- 状态每 5 秒轮询一次；页面隐藏时暂停轮询，回到页面立即刷新一次。
- 写操作期间暂停轮询，避免状态闪烁。
- 刷新时保留列表的滚动位置和展开中的菜单。
- 深色和浅色主题都使用主题变量，不写死颜色。
- 列表为空时显示空状态：「还没有设置设备出口」加一个 [+ 添加设备] 按钮。

## 10. 技术方案（交给实现方，必须遵守的不变量）

### A. 出口分流（随 OpenClash 运行时存在）

- 每台启用的设备生成一个 mihomo `tproxy` 入站 listener，端口为 `7900 + 序号`，并设置 `proxy: <出口名>`。
  - Mihomo 已确认：设置了 SpecialProxy 时不看 mode 和 rules，出口不存在则直接报错（`tunnel/tunnel.go:317-325`）。因此不受全局 / 直连模式影响，节点缺失时也不会回退直连。
  - 端口要检查与 OpenClash 已用端口不冲突。
- nftables：对 `ether saddr <MAC> ip saddr <IP>`、目的地址不在 localnetwork 的 TCP 和 UDP 流量做 tproxy 到该设备的端口，使用独立的 fwmark 和路由表（local default dev lo）。
- OpenClash 原有的所有拦截链（redirect、tproxy、TUN 打标、大陆绕过、黑白名单、lan_ac_traffic、仅代理常用端口）开头加一条：命中 `@openclash_bound_macs` 就 return，保证绑定设备只走 A。
- DNS（53 端口）：OpenClash 开启 DNS 劫持时照常劫持；关闭时，53 端口也走设备出口。
- 修改设备列表时优先热重载内核；做不到热重载时才重启。

### B. 断网保护（持久存在，与 OpenClash 进程无关）

- 独立的表 `inet openclash_guard`：
  - forward 链 priority -10：绑定 MAC 发往非 LAN 设备的流量一律 drop，包括 IPv6。
  - prerouting 链：绑定 MAC 的源 IP 不是绑定 IP、且目的地址不在 LAN 时 drop。
- 在设备上验证 forward 链里 `ether saddr` 能否匹配；不能匹配就改为在 prerouting 里打 ct mark，再在 forward 里按 ct mark 匹配。
- 加载时机：
  - 开机由 `/etc/init.d/openclash_guard`（START=18）加载；
  - fw4 的 `ruleset-post` include 负责在防火墙重载后重新加载；
  - 缓存文件 `/etc/openclash/device-guard.nft` 加入升级保留列表。
- OpenClash 的 stop、start_fail、restart、`revert_firewall` 都不能动这张表。只有设备列表变化时才重新生成它。没有启用的设备时删表。
- 生成失败时安装紧急策略（只允许 LAN 内部通信），并中止这次保存。
- 变更后 flush fw4 flowtable。
- 包被完全卸载时删除保护（文档写明）；升级时保留。

### D. 验收（必须在 192.168.50.1 真机上做）

对一台绑定设备分别测 TCP（HTTPS）和 UDP（STUN）：

1. 正常运行时，出口 IP 是节点的 IP；
2. 依次执行 stop、restart、kill 内核、让 start_fail 触发、fw4 reload、整机重启，其间都不能直连；
3. 切到全局和直连模式时仍走节点；
4. 切换到一个没有该节点的配置时设备被阻断；
5. 设备改 IP 后被阻断；
6. IPv6 被阻断；
7. 未绑定的设备行为不变。
